## C. Is the embedded-module wiring real? — yes, and here is the proof

`rust/wa-host/src/main.rs`'s `EMBEDDED` list carries `("lua/core/openai_sub_auth.lua", include_str!(…))`, and the host's `dofile` bootstrap serves `EMBEDDED` whenever `WASM_AGENT_LUA_ROOT` is unset (main.rs bootstrap, `embedded module missing: …` on a miss). Proven with a binary **the reviewer built** from `a6e111d` (`cargo build --release --offline`, 3 m 27 s exit 0), run from a directory with **no `lua/`** and with the root unset:

* the module is in the embedded registry; `dofile("lua/core/openai_sub_auth.lua")` returns a table with `token()`; `LOADED_SOURCES` records its sha256;
* **negative control**: `dofile("lua/core/definitely-not-registered.lua")` fails with `embedded module missing` — so the pass is not "dofile always answers";
* the embedded text is **byte-identical** to the working tree copy (`host.sha256` on both);
* the embedded copy actually runs: it answered the taxonomy code instead of crashing.
